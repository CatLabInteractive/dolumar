# Mobile-usable UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the full game playable on a phone by rendering the existing server-side windows as full-screen sheets, with a tab bar, compact header, pinch-zoom map and a touch flow for placing buildings, without changing the desktop UI.

**Architecture:** A client-side layout mode (`Game.layout`) decides `desktop` or `mobile` from a per-player preference and the viewport width. In mobile mode the engine's window manager puts each `window`-type dialog into a sheet stack instead of a Prototype Window Class dialog, the map viewer gains a CSS scale and a pinned-ghost placement flow, and the game restyles its Menu and Statusbar panels into a tab bar and header. The PHP windows and the dialog XML protocol do not change.

**Tech Stack:** PHP 8.4 (engine + game), Prototype 1.6 / script.aculo.us client code, Prototype Window Class, plain CSS with media-free class scoping (`body.layout-mobile`), PHPUnit 11 (engine), Playwright (Node, run from the host) for browser checks against the Docker stack.

**Spec:** `.ai/superpowers/specs/2026-11-02-mobile-ui-design.md` (game repository).

## Global Constraints

- Two repositories, same branch name in both: `claude/project-thread-d3x5ln`. Engine tasks live in `dolumar-engine`, game tasks in `dolumar`. The game's Docker stack mounts `../dolumar-engine` live, so engine changes are tested through the game (see `dolumar/.ai/development.md`).
- Desktop mode must be byte-for-byte the current code path: every new behaviour is guarded by `Game.layout.mode() === 'mobile'` or scoped under `body.layout-mobile`.
- No change to any `Dolumar_Windows_*` / `Neuron_GameServer_Windows_*` logic, to the dialog XML attributes, polling or form submission.
- Breakpoint: `window.innerWidth < 800` is mobile when the preference is `auto`. Zoom range `0.5` to `1.5`, step `0.25`. Tap targets at least `44px`.
- Preference key `layout`, values `auto | desktop | mobile`; the shipped default is `desktop` (staged rollout, spec §6). Query override `?layout=`.
- Zoom level stored in `localStorage` under key `dolumar.mapScale`.
- Nothing under `public/` may expose setup or login shortcuts; the local login mock is a separate Docker service, never part of the app.
- PHP: `failOnWarning/Deprecation/Notice` are on in the engine's PHPUnit; no warnings in AJAX output. Run `vendor/bin/phpcs` in both repos before each PR.
- Commit messages: plain, descriptive, no model identifiers. Every PR body starts with the attribution block the project requires.

## Review Focus

1. A window opened in mobile mode while another sheet is open must keep the hidden sheet polling; closing the top sheet must reveal the previous one with its content intact (Task 5 test `sheets-stack`).
2. Switching the preference from `mobile` to `desktop` (or resizing across 800px in `auto`) with windows open must not lose their content or create duplicate `aOpenWindows` entries (Task 6 test `relayout`).
3. At scale 0.5 the map must load tiles for the whole visible area, not only the centre quarter; at 1.5 panning must still follow the finger 1:1 (Task 7 test `map-scale`).
4. `?layout=foo` or a tampered stored preference must fall back to the default, never to an undefined mode (Task 3 test `testUnknownValuesFallBackToDefault`).
5. Cancelling a placement on mobile must restore the sheets and leave no `#map_select_actions` bar or overlay behind (Task 8 test `place-cancel`).
